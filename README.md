(27–28 жовтня 2026) із 95% інтервалом.

| файл | що це |

## Як запустити

**Локально:**

```bash
pip install -r requirements.txt
jupyter notebook project.ipynb
```

**У Google Colab:** File → Upload notebook, потім завантажити `train.csv` і
`weather_forecast.csv`, коли друга клітинка попросить.

Прогін зверху вниз: Kernel → Restart & Run All. Займає кілька хвилин; валідація на
шести вікнах — близько 15 секунд, бо порядок ARIMA заданий явно і пошуку немає.

Результат: файл `MIKHAILISHYNA_project.csv` із 48 рядками.

## Версії

```
statsforecast==2.1.1
pandas
numpy
matplotlib
statsmodels
```

Версія `statsforecast` зафіксована не для формальності. На етапі, коли специфікацію
підбирала `AutoARIMA`, її покроковий пошук на різних збірках numpy/scipy зупинявся в
різних точках: те саме вікно валідації дало RMSE 241.2 в Colab і 190.8 локально при
ідентичному коді. У фінальній моделі порядок заданий явно, тож ця нестабільність
усунена, але версію лишаю зафіксованою.

## Модель

`ARIMA(1,0,0)(0,1,1)[24]` з екзогенними регресорами, навчання на останніх 30 днях.
Сезонна різниця переносить значення тієї ж години попередньої доби, регресія додає
різницю в погодних умовах, AR(1) описує коротку інерцію, сезонний MA(1) — поправку
на вчорашню помилку тієї ж години.

Порядок заданий явно, а не через `AutoARIMA`: автоматичний пошук зупинявся на
`(0,0,0)(0,1,0)`, тоді як PACF залишків вказував на AR(1). Явна специфікація дала
MAPE 152 замість 242 на валідації і рахується за секунди замість хвилин.

Регресори: хмарність, температура, швидкість вітру, вологість, світловий день і куб
швидкості вітру; згладжені центрованим ковзним середнім на 3 години.

Ніч моделюється на логарифмічній шкалі окремо від дня. Три константи-поправки —
0.7 на нічний рівень, 0.95 на денний, 0.85 на ширину інтервалу — підібрані на
rolling-origin валідації. Обґрунтування кожної у звіті.
